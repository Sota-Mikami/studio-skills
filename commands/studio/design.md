# /studio:design — 方向確定のためのパターン出し（P3）

> **ループ内の位置**: P3。仮 Spec の後、方向を視覚で確定する（パターン選択＝方向の承認）。
> **いつ選ぶ**: 見栄え・トーンまで含めて方向を決めたい時。超早期の構造ラフだけなら `/studio:alt3`（グレースケール）。

$ARGUMENTS の UI について、**方向性の異なる 3-5 案**を作る（引数が無ければ、いま検討中の画面）。

## まず「この repo の実デザイン」を発見する（決め打ちしない）
塗る前に **DOCTRINE §プロジェクト固有値の「発見」** に従って読む（profile → 差分チェック → 穴埋め。デザイン正本・トークン・font・UI ライブラリの探し場所はそちらが正本）。

## 必ず守る
- **1枚の HTML に横並び**（`.studio/design/NN-slug.html`・案ごとに別ファイルにしない）。ブラウザ / Orca で見比べる。
- **発見した実デザインをラフ再現する（グレースケールにしない）**: 読み取った色・タイポ・余白・角丸・影に寄せ、UI ライブラリの見た目（フラット/角丸/影の質感）を真似る。**ブランドの禁則があれば守る**。推測値で塗らない。
- **実際に動く**: タブ切替・トグル・hover・アコーディオン等をインライン JS で入れ、**触って比較できる**ようにする（静止画にしない）。
- 各案に **ラベル（案 01/02…）＋トレードオフ1行**（何を取り何を捨てたか）。
- 該当画面の**周辺文脈**（ヘッダ/サイドバー等）も薄く含め、実アプリ内での見え方が分かるようにする。

## 出す前に自己批評（弱点3つ）
どれも凡庸でないか / 既存コンポーネントで実装可能か / ブランド禁則を破っていないか。

## 最後に
**AskUserQuestion で「どの案を採用するか」を聞く**（各案を選択肢に・推奨を添えてよい）。まだ実装はしない — 採用が決まってから P4（`/studio:implement`）へ。
